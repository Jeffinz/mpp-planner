## UI foundation and the missing tokens (evening)
- Shipped dialogs (`<dialog>`, in-page confirm), the Playwright e2e harness on the emulators, the loading message, and moved colors/radii/spacing into CSS tokens.
- The UI then looked wrong (no padding, no gaps, square corners, no dark backdrop). Root cause: b131fc3 swapped literals for `var(--space-*)`, `var(--radius*)` and 9 more, but never declared them in `:root`. Browsers drop a declaration whose `var()` is undefined, silently. All 5 e2e tests passed anyway because they click buttons; they never look.
- Found it by screenshotting the app with a throwaway Playwright spec (desktop 1280 and mobile 390) after the Chrome extension was not connected. Fixed in 62fb57d with a unit test that fails on any `var(--x)` with no definition. Lesson: a refactor that changes how values are looked up needs a check on the lookup, not only on behavior.
- My first suspicion (`.list{display:flex}` beating `hidden`) was wrong: `[hidden]{display:none !important}` already exists. Read the CSS before theorizing.
